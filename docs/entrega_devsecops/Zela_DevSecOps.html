Transparência sobre o pipeline. O GitHub Actions da conta do repositório está bloqueado por um problema de cobrança do GitHub ("account is locked due to a billing issue"), e os jobs não chegam a executar. O workflow está no repositório. Todas as verificações dele foram rodadas localmente com as mesmas ferramentas e estão documentadas na seção 2. O job de deploy também depende de um acesso OIDC ao Azure ainda não criado, então a publicação foi feita manualmente com os mesmos passos do job.

1. Arquitetura

Código-fonte do diagrama em docs/arquitetura.md. Toda a infraestrutura do Azure é criada por Terraform. O pipeline só publica a imagem.

Fluxo de entrega

  1. Um push na main dispara o workflow ci.
  2. Rodam em paralelo: testes (pytest), Gitleaks (segredos no histórico), Semgrep (SAST de Python e Dockerfile) e terraform validate.
  3. O Trivy varre a imagem e reprova o pipeline se houver vulnerabilidade HIGH ou CRITICAL com correção disponível.
  4. Só se tudo passar, o job deploy entra no Azure por OIDC (sem senha guardada), publica a imagem no ACR com o SHA do commit, atualiza o Container App e confere o /health.

Alerta disparado

O alerta zela-erros-5xx (Azure Monitor, consulta nos logs do contêiner) avisa por e-mail quando passa de 5 respostas 5xx em 5 minutos. Depois de 10 respostas 500 provocadas de propósito, ele entrou em Fired às 19:36 UTC de 11/11/2026 (gravidade Sev2). A prova está em infra/evidencias/alerta_disparado.json. Não foi verificado se o e-mail chegou à caixa de entrada.

Dois problemas foram achados e corrigidos no caminho: a métrica Requests do Container App não entrega a divisão por categoria de status, então o primeiro alerta (por métrica) nunca dispararia e foi trocado por consulta nos logs; e erros 500 não tratados não eram contados no /metrics da API, o que foi corrigido com teste automático.

6. Dados pessoais (LGPD)

Dados tratados: foto da via, localização (texto e coordenadas) e descrição livre. Ficam no PostgreSQL e no disco do contêiner, na região spaincentral (União Europeia, o que configura transferência internacional). O relato é anônimo: não coletamos nome, CPF, telefone nem e-mail. A foto tem o EXIF (GPS e modelo do aparelho) removido no upload. O OpenRouter recebe só as dúvidas de uso do FonteBot, nunca fotos ou relatos. Detalhes em docs/custos_e_lgpd.md.

Riscos conhecidos que ainda não foram tratados

  • Leitura pública da API: a listagem de relatos, o relato por id e a foto não exigem login, porque o painel da demo as consome. Qualquer pessoa com a URL vê localizações e fotos.
  • Sem rota de exclusão nem prazo de retenção definido para os relatos.
  • Fotos em disco efêmero: somem a cada novo deploy do contêiner. Azure Files resolveria.
  • Texto livre pode receber dados pessoais. /metrics é público (só contadores agregados).
  • Estado do Terraform local: guarda a senha do banco. Em produção, usar backend remoto criptografado.

8. Como reproduzir

git clone https://github.com/phz1n777/zela.git && cd zela
cp .env.example .env            # preencha tokens e senha
docker compose up --build       # API em http://localhost:8000

# Monitoramento contra o MVP publicado
PROM_CONFIG=prometheus-azure.yml docker compose -f docker-compose.monitoring.yml up prometheus grafana

# Nuvem (conta Azure for Students)
cd infra/terraform && cp terraform.tfvars.example terraform.tfvars
terraform init && terraform plan -out tf.plan && terraform apply tf.plan
